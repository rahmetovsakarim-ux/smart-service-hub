| NFR-02 | Масштабталу | Жүйе пайдаланушылар мен тапсырыс санының өсуіне төзімді болуы тиіс | Мақсатты көрсеткіш: бір мезгілде 500 пайдаланушыға дейін; жаңа қала қосу кодты өзгертпей жүргізіледі |

| NFR-06 | Сүйемелдеу мүмкіндігі | Жүйе қабатты архитектурамен құрылып, код GitHub-та жүргізілуі тиіс | Controller — Service — Repository қабаттары; әр модуль бөлек пакетте |
| NFR-07 | Өзара әрекеттесу мүмкіндігі | Сыртқы жүйелермен стандартты интерфейс арқылы байланысу тиіс | REST API (JSON); SMS/Push және төлем шлюзімен интеграция |
| NFR-08 | Сыйымдылық | Дерекқор тапсырыс тарихын жинақтап сақтай алуы тиіс | ≥ 100 000 тапсырыс жазбасында жұмыс тұрақты |
| NFR-09 | Икемділік | Жаңа қызмет категориясын кодты өзгертпей қосуға болуы тиіс | Каталог Әкімші интерфейсі арқылы өзгертіледі |
| NFR-10 | Пайдалану шектеулері | Технологиялық және құпиялылық шектеулері сақталуы тиіс | Java + Spring Boot, MySQL, веб-қосымша; клиенттің телефоны мен мекенжайы тек тағайындалған маман мен Әкімшіге көрінеді |

## 3. User Story

| **ID** | **User Story (Card)** | **Қабылдау критерийлері (Confirmation)** |
| --- | --- | --- |
| US-01 | Мен клиент ретінде, қызметті категория бойынша іздегім келеді, себебі қажетті маманды жылдам табуым керек. | Категория таңдалғанда сәйкес қызметтер тізімі баға мен сипаттамасымен көрінеді; нәтиже ≤ 3 секундта шығады. |
| US-02 | Мен клиент ретінде, қызметті дауыспен іздегім келеді, себебі мәтінді қолмен теруге уақыт жұмсамауым керек. | Айтылған сөз мәтінге айналып, іздеу жолына түседі; сөз танылмаса, жүйе қайта айтуды ұсынады. |
| US-03 | Мен клиент ретінде, қызметке онлайн тапсырыс (мекенжай, уақыт) қалдырғым келеді, себебі қоңырау шалып ұзақ келісуден құтылуым керек. | Барлық міндетті өріс толтырылғанда тапсырыс статус = New күйінде тіркеліп, нөмірі беріледі; өріс бос болса, қате көрсетіледі. |
| US-04 | Мен клиент ретінде, тапсырысымның статусын нақты уақытта көргім келеді, себебі маманның қашан келетінін білуім керек. | Тапсырыс бетінде New / Accepted / In Progress / Completed статусы көрінеді; статус өзгергенде хабарлама келеді. |
| US-05 | Мен клиент ретінде, орындалған қызметке баға мен пікір қалдырғым келеді, себебі басқа клиенттер сапалы маманды таңдай алуы керек. | Баға (1–5) тек Completed тапсырысқа қойылады; сақталғаннан кейін маманның рейтингі жаңарады. |
| US-06 | Мен маман ретінде, маған тағайындалған тапсырыстарды көріп, қабылдағым немесе бас тартқым келеді, себебі жұмыс кестемді өзім басқаруым керек. | Маманға өзінің тапсырыстар тізімі ғана көрінеді; қабылдағанда статус Accepted болады, бас тартқанда Әкімшіге хабарлама кетеді. |
| US-07 | Мен маман ретінде, орындау барысында тапсырыс статусын жаңартқым келеді, себебі клиент пен әкімші процесті көріп отыруы керек. | Статусты тек келесі қадамға ауыстыруға болады (Accepted → In Progress → Completed); әр өзгеріс клиентке хабарланады. |
| US-08 | Мен әкімші ретінде, тапсырысқа маманды қолмен тағайындағым келеді, себебі автоматты іздеу нәтиже бермесе, тапсырыс тоқтап қалмауы керек. | Escalation-хабарламадан кейін Әкімші тапсырысқа бос маманды таңдай алады; маманға хабарлама жіберіледі. |
| US-09 | Мен әкімші ретінде, қызметтер каталогын басқарғым келеді, себебі қызмет түрлері мен бағалар өзекті болуы керек. | Әкімші қызметті қоса, өңдей және өшіре алады; өзгеріс клиент каталогында бірден көрінеді. |
| US-10 | Мен әкімші ретінде, тапсырыс статистикасын көргім келеді, себебі қызмет сапасын бақылап, шешім қабылдауым керек. | Dashboard-та тапсырыс саны статус, маман және кезең бойынша көрсетіледі. |

**Conversation — талқылауға арналған мәселелер.** US-02 бойынша дауыс тану қай тілдерде (қазақ, орыс) жұмыс істеуі керек; US-03 бойынша тапсырыс уақыты бос слот ретінде таңдала ма, әлде еркін енгізіле ме; US-08 бойынша автоматты іздеу маманды қандай белгімен (жақындық, рейтинг, жүктеме) таңдайды. Бұл сұрақтар әзірлеу кезінде мүдделі тараптармен нақтыланады.


## 4. Талаптардың іске асырылуы (traceability)

| Талап | Қайда жүзеге асқан |
| --- | --- |
| FR-01 | `AuthController`, `AuthService`, `AppUserDetailsService` (телефон НЕМЕСЕ e-mail арқылы кіру), `#/register`, `#/login` |
| FR-02 | `SecurityConfig` (`/api/admin/**` → ADMIN, `/api/worker/**` → WORKER, `/api/client/**` → CLIENT; бөтен рөл → 403) |
| FR-03 | `CatalogController`, `CatalogService.search`, `ServiceItemRepository.search*`; UI: каталог + санат чиптері + іздеу |

| FR-05 | `OrderService.create` — статус `NEW`, дерекқорға жазу, бағаны сақтау |
| FR-06 | `WorkerSearchService` (санат → бос уақыт → аудан → рейтинг → жүктеме); қолмен: `AdminController.assign` |
| FR-07 | `WorkerController.accept/reject`, `OrderService.changeStatus/reject` |
| FR-08 | `OrderStatus.canMoveTo` (тек бір қадам алға) + `OrderStatusTest` |
| FR-09 | `NotificationService` → БД (қоңырау белгісі, 10 с сайын жаңарады) + `SmsPushProvider` |

| FR-11 | `PaymentService` + `PaymentGateway` (демо `MockPaymentGateway`); сәтсіз талпыныс та тіркеледі |
| FR-12 | `AdminController`: санаттар, қызметтер (CRUD), пайдаланушыларды бұғаттау |
| FR-13 | `StatisticsService`, UI: Басқару тақтасы (статус / маман / күн бойынша, 7-14-30 күн) |
| FR-14 | `NotificationService.escalationNoWorker`, `workerRejected` → барлық Әкімшілерге |
| FR-15 | `order_status_history` кестесі, тапсырыс бетіндегі «Өзгерістер тарихы» |
| NFR-01 | Индекстер, жеңіл JSON API, іздеу 300 мс debounce |
| NFR-02 | Stateless қызметтер қабаты, тізімдерге 200 жазба шегі, `Districts`/каталог — деректермен басқарылады |
| NFR-03 | BCrypt; HTTPS баптауы `application.properties` ішінде; рөлдік қорғаныс |

| NFR-07 | REST API (JSON), `SmsPushProvider` және `PaymentGateway` интерфейстері |
| NFR-08 | `orders` кестесінде status / client / worker / created_at индекстері |
| NFR-09 | Жаңа санат/қызмет Әкімші интерфейсі арқылы, код өзгертпей |
| NFR-10 | Java 17 + Spring Boot + MySQL, веб-қосымша; клиенттің телефоны мен мекенжайы тек тағайындалған маманға және Әкімшіге көрінеді (`OrderService.get` қатынас тексеруі) |
